# 原项目分析

> 对象：`/home/shitanli/ln_rebuild_zcode/nanobot/nanobot`（HKUDS/nanobot v0.3.5，Python 3.11+，约 41.5 万行 Python 中核心包 16.5 万行）。
> 用途：教学重建时的对照与验证，只读。

## 1. 业务定位

nanobot 是一个**超轻量、自托管、个人 AI agent 运行时**。一句话：把"一个能用工具、有记忆、多渠道接入的个人 AI 助手"做成一个小而可读的 Python 服务。

- **谁用**：个人开发者 / 技术爱好者，自托管（本机或自己的服务器）。
- **为什么需要**：不想依赖大平台托管的服务；想自己控制模型选择、数据、工具和扩展。
- **一次最普通的成功运行**（Happy Path）：
  1. 用户在终端 / WebUI / Telegram 发一条文本消息；
  2. 框架把它装进 `InboundMessage` 投入消息总线；
  3. AgentLoop 取出消息，找到（或新建）该用户的 Session；
  4. 组装上下文（system prompt + 历史消息 + 当前消息）发给 LLM；
  5. LLM 若要求调用工具（读文件、执行 shell、搜索…）→ 执行工具 → 结果回填 → 再次调 LLM，循环直到 LLM 给出最终文本；
  6. 最终回复与过程消息写回 Session 持久化；
  7. 回复以 `OutboundMessage` 投回总线，由渠道发给用户（通常流式逐字送达）。

## 2. 总体架构与模块职责

```text
渠道层        CLI / WebUI(WS) / Telegram / Discord / Slack / 邮件 / … (channels/, cli/, webui/)
                │ InboundMessage                        ▲ OutboundMessage / 事件
消息总线       MessageBus（asyncio.Queue 入/出双队列 + 进程内订阅者）(bus/)
                ▼                                       
编排层         AgentLoop（每会话一个 worker，turn 六阶段流水线）(agent/loop.py)
                ▼
执行层         AgentRunner（LLM+工具 while 循环）        (agent/runner.py)
              ├─ ContextBuilder 组装 prompt             (agent/context.py)
              ├─ ContextGovernor token 预算/压缩        (agent/context_governance.py)
              ├─ ToolRegistry / execute_tool_calls      (agent/tools/)
              └─ LLMProvider（chat / chat_stream）      (providers/)
                ▼
数据层         SessionManager（JSONL 会话文件 + LRU）    (session/manager.py)
              MemoryStore（MEMORY.md/SOUL.md/USER.md）  (agent/memory.py)
              LLMUsageStore（SQLite 用量统计）           (llm_usage/)
```

### 关键模块速览

| 模块 | 核心类 | 职责 |
|---|---|---|
| `agent/loop.py` | `AgentLoop` | 消息接入与编排骨架；turn 六阶段：restore → compact → command → build → run → save → respond |
| `agent/runner.py` | `AgentRunner` | 产品层无关的 LLM+工具循环本体（`_run_core`）；输出 `AgentRunResult` |
| `agent/context.py` | `ContextBuilder` | system prompt（身份文件+工具契约+记忆+技能摘要）与 transcript 组装 |
| `agent/context_governance.py` | `ContextGovernor` | 请求前消息清洗、token 预算、超限压缩为摘要 |
| `agent/tools/` | `Tool`(ABC) / `ToolRegistry` / `ToolLoader` / `execute_tool_calls` | 工具定义-注册-发现-执行四件套；并发调度 |
| `agent/memory.py` | `MemoryStore` / `Consolidator` / Dream | 长期记忆文件读写；会话摘要压缩；后台记忆巩固 |
| `agent/subagent.py` | `SubagentManager` | 子代理＝一个 `spawn` 工具；受限工具集、复用 AgentRunner |
| `providers/base.py` | `LLMProvider`(ABC) / `LLMResponse` / `ToolCallRequest` / `LLMUsage` | 模型调用统一抽象；重试；流式默认实现 |
| `providers/openai_compat_provider.py` | `OpenAICompatProvider` | 覆盖绝大多数后端（含 DeepSeek/智谱/Ollama 等）；流式聚合 |
| `providers/anthropic_provider.py` | `AnthropicProvider` | Anthropic 原生协议转换（消息格式/cache/thinking） |
| `providers/fallback_provider.py` | `FallbackProvider` | 请求级故障转移 + 主 provider 熔断 |
| `providers/registry.py` / `factory.py` | `ProviderSpec` / `make_provider` | 按 key/base/模型名匹配厂商 spec 并装配 |
| `session/manager.py` | `Session` / `SessionManager` / `JsonlSessionStore` | 会话建模与 JSONL 持久化（原子重写+LRU 缓存+崩溃恢复） |
| `bus/queue.py` | `MessageBus` | 入/出双队列，解耦渠道与 agent 核心 |
| `events.py` | `AgentEvent` 家族 / `EventSink` | 传输无关的操作通知（重试/压缩/恢复） |
| `config/` | `Config`(pydantic) / `load_config` | `~/.nanobot/config.json`；环境变量覆盖；热重载 |
| `nanobot/nanobot.py` | `Nanobot` | SDK 门面：`run()` / `run_streamed()` → `AgentLoop.process_direct` |
| `cli/` | typer 应用 | `agent`(终端) / `serve`(OpenAI 兼容 API) / `gateway`(常驻 WebUI/渠道) / `webui` |
| `api/server.py` | aiohttp 应用 | `/v1/chat/completions`（含 SSE 流式）、`/v1/models`、`/health` |
| `gateway/` | `GatewayRuntime` / `GatewayServiceInstaller` | 后台常驻进程管理、systemd/LaunchAgent 安装 |
| `llm_usage/` | `LLMUsageStore` | 内容无关的调用统计（SQLite 单表 `llm_calls`） |
| `cron/` / `triggers/` | `CronService` 等 | 定时/触发自动化（含 Dream 记忆巩固任务） |

## 3. 入口链路（程序怎么跑起来）

- **CLI 单次/交互**：`python -m nanobot` → `cli/entry.py::main`（快路径：裸 `agent` 命令不加载完整 CLI 图）→ `cli/agent.py::agent` → `make_provider(config)` → `AgentLoop`。
- **SDK**：`Nanobot.from_config()` → 内部同样构建 `AgentLoop`；`bot.run(msg)` → `loop.process_direct`。
- **OpenAI 兼容服务**：`nanobot serve` → `api/server.py::create_app`（aiohttp）→ 每请求调 AgentLoop。
- **常驻网关（WebUI/多渠道）**：`nanobot gateway` → `cli/gateway_runtime.py::_run_gateway`：MessageBus → provider snapshot → SessionManager → CronService → 工具/MCP → AgentLoop → ChannelManager + WebUI 静态服务 + 配置热重载。
- **provider 构建**：`load_config`(JSON) → `Config._match_provider`（registry 优先级匹配：显式指定 > 模型前缀 > keyword > 本地兜底）→ `factory._make_provider_core`（按 backend 分派）→ 可选 `FallbackProvider` 包装 → `ProviderSnapshot`。

## 4. 工程复杂度真正来自哪里

按占用篇幅和分支数排序：

1. **健壮性兜底**：provider 重试矩阵（指数退避、Retry-After、流中断恢复、空回复重试、length 续写）、会话崩溃 checkpoint、JSONL 损坏修复、孤儿 tool 结果清洗。
2. **协议/厂商适配**：registry 里数十家厂商 spec、Anthropic 与 OpenAI 消息互转、Responses API 状态续写、OAuth 系列（codex/grok/copilot）。
3. **上下文治理**：token 预算、工具结果字符预算+落盘 offload、历史摘要压缩（Consolidator）、AutoCompact。
4. **多渠道产品层**：161 个渠道文件、TurnDelivery 路由、事件受众策略、WebUI 前后端。
5. **外围系统**：MCP 全套集成（~2600 行）、gateway 进程管理、用量统计、cron/triggers、skills、插件。

**而核心骨架（真正值得教学的主线）其实很小**：一条"消息 → 上下文 → LLM → 工具循环 → 持久化 → 回复"的链，加上工具四件套和 provider 抽象。这是教学重建的主干，其余按演化节奏选择性引入。

## 5. 测试风格（教学可借鉴）

- pytest + pytest-asyncio（`asyncio_mode = "auto"`）。
- 核心手法：**手写 Fake/Failing Provider 继承 `LLMProvider` 注入**（如 `tests/agent/test_runner_fallback.py` 的 `_FakeProvider`），不打真实网络。
- conftest 用 monkeypatch/fixture 隔离存储目录（会话、配对等不落真实家目录）。
- 教学项目采用同样的"假对象注入"思路，从第 1 课开始。
