# 数据模型

> nanobot 的核心数据长什么样、存在哪。路径相对 `nanobot/nanobot/nanobot/`。

## 1. 消息（Message）—— 无 schema 的 OpenAI 风格 dict

消息**不是 pydantic 模型**，就是普通 dict（OpenAI Chat 风格 + 私有扩展键），由 `Session.add_message`（`session/manager.py:208`）追加并自动盖 `timestamp`。

```jsonc
// 用户消息
{"role": "user", "content": "帮我看看这个报错", "timestamp": "2026-09-24T10:20:01",
 "media": ["/path/to/img.png"]}

// 助手消息（带工具调用）
{"role": "assistant", "content": null,
 "tool_calls": [{"id": "call_abc", "type": "function",
                  "function": {"name": "read_file", "arguments": "{\"path\":\"a.py\"}"}}],
 "reasoning_content": "(可选,DeepSeek/Kimi 思维链)"}

// 工具结果消息
{"role": "tool", "tool_call_id": "call_abc", "name": "read_file",
 "content": "(文件内容或错误文本)"}

// 助手最终回复
{"role": "assistant", "content": "看完了,问题是……", "latency_ms": 3200}
```

- 私有下划线键（`_hidden_history`、`_automation_turn`、`_command` 等）控制回放可见性，不发给 LLM。
- 回放投影 `Session.get_history`（`manager.py:240-372`）：按归档水位切片、media 合成面包屑、截断时保持 tool-call 配对完整。

## 2. 会话（Session）—— JSONL 文件 + LRU 内存缓存

**不是数据库**。每个会话一个 JSONL 文件，路径 `<数据目录>/sessions/<workspace-id>/<base64url(session_key)>.jsonl`：

```jsonc
{"_type": "metadata", "key": "telegram:12345", "created_at": "...", "updated_at": "...",
 "metadata": {"title": "..."}, "last_archived": 12}
{"_type": "provider_state", "state": {"kind": "openai_responses", "payload": {...}}}   // 可选
{"role": "user", "content": "你好", "timestamp": "..."}
{"role": "assistant", "content": "你好呀", "timestamp": "..."}
```

- `Session` dataclass（`session/manager.py:171`）：`key`（格式 `channel:chat_id`）、`messages: list[dict]`、`metadata`、`provider_state`、`policy`（运行时规则，不持久化）。
- 写入 = **全量原子重写**（临时文件 + `os.replace`），filelock 保护；损坏行在加载时跳过修复。
- `SessionManager` 维护 128 上限的 LRU；`flush_all` 关机落盘。
- 会话键约定（`session/keys.py`）：`unified:default`、`channel:chat_id`、`dream:*`、`heartbeat`。

## 3. LLM 请求/响应（providers 层统一格式）

请求侧：消息列表 + 工具 schema 列表 + 采样参数。响应侧统一为 `LLMResponse`（`providers/base.py:566`）：

```python
LLMResponse(
    content="回复文本或 None",
    tool_calls=[ToolCallRequest(id, name, arguments_json)],   # base.py:71
    finish_reason="stop" | "tool_calls" | "length" | "error" | "cancelled",
    usage=LLMUsage(input_tokens, output_tokens, ...),          # base.py:281
    reasoning_content=None, thinking_blocks=None,              # 思维链(各厂商)
    provider_state=None,                                        # 原生续写状态
)
```

`should_execute_tools` 属性：`finish_reason ∈ {tool_calls, function_call, stop}` 且有 tool_calls 才执行工具。

工具 schema 走 OpenAI function 格式（`Tool.to_schema()`，`agent/tools/base.py:313`）：

```json
{"type": "function", "function": {
  "name": "get_time", "description": "获取当前时间",
  "parameters": {"type": "object", "properties": {"tz": {"type": "string"}},
                  "required": []}}}
```

`ToolResult`（`base.py:149`）：带 `is_error` 标志的字符串，序列化为 `role:"tool"` 消息 content。

## 4. 总线消息（bus/）

```python
InboundMessage(channel="telegram", sender_id="u1", chat_id="123",
               content="你好", media=[], session_key_override=None)
OutboundMessage(channel="telegram", chat_id="123", content="回复",
                reply_to=None, media=[], event=None)   # event 可携带 StreamDeltaEvent 等
```

事件家族（`bus/outbound_events.py` + `events.py`）：`ProgressEvent`、`StreamDeltaEvent/StreamEndEvent`、`TurnEndEvent`、`RetryWaitEvent/RetryStatusEvent`、`ContextCompactionEvent` 等，由渠道决定投影方式。

## 5. 长期记忆（文件 + git）

工作区内固定文件（`agent/memory.py:59` `MemoryStore`）：

```text
workspace/
├── SOUL.md              人格
├── USER.md              用户画像
└── memory/
    ├── MEMORY.md        长期事实
    ├── history.jsonl    追加式日志 {"cursor": 41, "timestamp": "...", "content": "..."}
    └── .dream_cursor    Dream 消费水位
```

- 会话摘要（Consolidator）→ checkpoint 存 Session metadata `_last_summary`，同时 journal 进 history.jsonl。
- Dream（后台巩固任务）：读 `.dream_cursor` 之后的 history 条目 → 用受限工具的临时会话编辑三个记忆文件 → 推进游标 → git 提交。
- 层次：**短期=会话 messages → 摘要 checkpoint → history.jsonl → MEMORY.md（长期）**。

## 6. 用量统计（唯一 SQLite）

`llm_usage.sqlite3` 单表 `llm_calls`（`llm_usage/store.py:196`）：

```text
id | started_at_ms | duration_ms | provider | model | source(user/api/cron/dream/system)
   | stream | finish_reason | input_tokens | output_tokens | ... | error_status_code | error_kind
```

只记 token/延迟/错误，**不存对话内容**（content-free）。保留 400 天 / 10 万条。

## 7. 配置（JSON + pydantic）

`~/.nanobot/config.json`（`config/schema.py`）：

```jsonc
{
  "agents": {"defaults": {"model": "anthropic/claude-opus-4-5", "provider": "auto",
                            "max_tokens": 8192, "context_window_tokens": 200000,
                            "temperature": 0.1, "fallback_models": []},
             "model_presets": {"快速": {"model": "deepseek-chat"}}},
  "providers": {"deepseek": {"api_key": "sk-..."},
                 "ollama": {"api_base": "http://127.0.0.1:11434/v1"}},
  "api": {"host": "127.0.0.1", "port": 8900},
  "gateway": {"host": "127.0.0.1", "port": 18790},
  "tools": {"exec": {"enabled": true}, "mcp_servers": {}}
}
```

环境变量 `NANOBOT_*` 可覆盖；支持 `${VAR}` 引用；热重载按 provider signature 比对决定是否重建。

## 8. 教学项目中的对应物（演化终点对照）

| 数据 | 原项目 | 教学项目计划 |
|---|---|---|
| 消息 | OpenAI 风格 dict + 私有键 | 同款 dict（核心教学对象，第 1 课引入） |
| 会话存储 | JSONL + LRU + checkpoint + 损坏修复 | JSONL + 原子写（第 5 课）；LRU/修复省略 |
| LLMResponse | 全字段统一 dataclass | 逐步长出：content → tool_calls → finish_reason → usage |
| 工具 schema | 类型化 Schema 构建器 + 装饰器 | 手写 dict schema（第 3 课）→ 基类自动生成（第 4 课） |
| 记忆 | 三文件 + history.jsonl + Dream + git | MEMORY.md + remember 工具（第 13 课）；Dream 简述不实现 |
| 用量 | SQLite 单表 | 省略（扩展课素材） |
| 配置 | pydantic + 环境变量 + 热重载 | JSON + 校验（第 14 课）；热重载省略 |
