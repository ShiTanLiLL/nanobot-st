# 第三方依赖

> nanobot 的依赖清单，以及教学项目中"何时、为什么"引入的对照。
> 教学原则：不第一课全装；每个组件进场前必须先有它解决的真实问题。

## 1. 原项目依赖分组（pyproject.toml）

### A. 核心骨架类

| 依赖 | 用途 | 教学引入时机 |
|---|---|---|
| `openai`（SDK） | OpenAI 兼容 Chat/Responses API 客户端；绝大多数厂商走它 | **第 1 课**（唯一初始依赖之一） |
| `anthropic`（SDK） | Anthropic 原生协议 | 第 16 课（第二个 provider 出现时） |
| `httpx` | 异步 HTTP（含 SOCKS 代理） | 按需（教学项目用不到代理时可不装；若 HTTP API 课用 aiohttp 则不引入） |
| `pydantic` + `pydantic-settings` | 配置模型与校验、环境变量 | 第 14 课（配置系统） |
| `typer` + `rich` | CLI 框架与终端美化 | 不引入——教学项目用简单的 `input()`/`argparse` 或直接 `python -m`，把认知负荷留给业务 |
| `loguru` | 结构化日志 | 不引入——用标准 `logging`（甚至先 print），第 8 课前后可视情况讲 logging |
| `prompt-toolkit` / `questionary` | 高级终端交互 | 不引入（教学 REPL 用 input()） |

### B. 工具/能力类

| 依赖 | 用途 | 教学处理 |
|---|---|---|
| `mcp` | Model Context Protocol 客户端与工具桥接 | 省略（扩展课素材） |
| `ddgs` | 网页搜索工具后端 | 省略或扩展课 |
| `croniter` | cron 表达式解析 | 省略（扩展课） |
| `jinja2` | 提示词模板渲染 | 省略（f-string 足够教学） |
| `tiktoken` | token 计数 | 省略——教学用"字符数/4"粗估并讲概念 |
| `json-repair` | 修复模型输出的残缺 JSON | 省略（讲现象即可） |
| 文档解析（pypdf/python-docx/openpyxl/python-pptx） | 读 PDF/Office | 省略 |
| `readability-lxml` 等 | 网页正文提取 | 省略 |
| `dulwich` | 纯 Python git（记忆版本化） | 省略（如做记忆 git 化可用系统 git 命令） |
| `rapidfuzz` | 工具名拼写建议 | 省略 |

### C. 基础设施类

| 依赖 | 用途 | 教学处理 |
|---|---|---|
| `websockets` | WebUI WS 通道 | 第 15 课视方案（若做 SSE 则不需要） |
| `aiohttp`（optional `api`） | OpenAI 兼容 HTTP 服务 | 第 15 课引入（或选标准库/其他框架，届时按教学效果定） |
| `filelock` | 跨进程文件锁（会话写入） | 省略——单进程教学版不需要 |
| `watchfiles` | 配置热重载 | 省略 |
| `setproctitle` / `packaging` / `tzdata` 等 | 杂项 | 省略 |
| `qrcode` / `oauth-cli-kit` | 配对/OAuth | 省略 |

### D. 开发依赖（原项目 dev）

`pytest`、`pytest-asyncio`、`ruff`、`basedpyright`、`pytest-cov/xdist` 等。教学项目引入：**pytest + pytest-asyncio（第 1 课）**、ruff（可选，讲了代码规范再装）。类型检查器省略。

## 2. 教学项目依赖演化时间线

```text
第 1 课    openai（SDK）、pytest
第 2 课    pytest-asyncio（转入异步）
第 7 课    （无新依赖——openai SDK 自带流式）
第 14 课   pydantic
第 15 课   aiohttp（或届时选型）
第 16 课   anthropic
```

其余一律不装。教学项目的"小而可读"目标优先。

## 3. openai SDK 教学要点备忘（第 1 课就会用到）

- `OpenAI(api_key=..., base_url=...)`：**base_url 一改就能接任何 OpenAI 兼容服务**（DeepSeek、智谱、Ollama、vLLM…）——这是国内可用性的关键，也是原项目 registry 生态的根基。
- `client.chat.completions.create(model, messages, tools=None, stream=False)` 为基本形态。
- messages 格式（role/content/tool_calls）本身就是行业事实标准，教学项目全程沿用。
- 环境变量约定：`OPENAI_API_KEY`（SDK 自动读）、`OPENAI_BASE_URL`、自定 `NANOBOT_ST_MODEL`。
