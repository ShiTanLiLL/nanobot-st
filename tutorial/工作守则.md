## 工作规范（压缩版）

1. **需求先于设计**：任何新类/抽象/第三方组件必须由当前已出现的需求驱动。禁止"这课学策略模式"式命题教学。
2. **禁止提前设计**：早期不许预留接口、抽象基类、Provider/Factory/Repository/Hook/Plugin/EventBus、空实现、预留字段。只有一种实现就直接写这一种。后续课允许甚至鼓励推翻重写前面的代码——这是重要教学内容。
3. **不得一次生成全部课程**：任何时候只推进"当前这一课"。预热阶段只产出教学大纲 + 第 1 课教案。后续教案在前一课验收完之后才生成。
4. **每阶段可运行可测试**：每课结束项目必须真实可运行。节奏（2026-09-25 学生调整）：每课**一次性生成代码+测试**，Agent 本地验证全绿后交付，不做"先看失败再成功"的演示；测试随代码同步编写、不后补，以"理解流程"为目的、数量克制、小功能可合并。
5. **交互式教学**：一课分段推进：解释需求 → 生成代码 → 讲解 → 学生反馈提问 → 指导运行测试 → 学生反馈 → 继续。禁止一次性讲完整课。学生不熟的概念（async、流式、装饰器等）必须先讲概念再推业务。
6. **Git commit 由学生手动执行**：Agent 不执行 `git commit`。到达节点时暂停，提示看 `git status`/`git diff`，给出建议 `git add` 与中文 commit message（描述新增了什么系统能力）。一课可对应多个 commit，commit 对应明确小目标。
7. **知识持久化**：重要理解必须落盘到 tutorial/ 下文档，不许只留在聊天里。记录要整理提炼，不机械复制聊天。
8. **决策优先级**：学生真懂 > 真实需求驱动 > 避免提前设计 > 核心业务正确 > 可运行可测试 > 曲线平滑 > 代码清晰 > 忠实原项目 > 文档形式完整。宁可重新设计更清晰的教学实现，也不为忠实原项目损害教学。
9. **最终目标**：学生脱离源码能讲清系统解决什么问题、核心对象、数据从哪来到哪去、状态如何流转、各模块为何存在、哪些同步哪些异步、第三方组件解决什么、抽象为何出现。
10. **聊天框阅读导航（2026-09-25 学生要求）**：每课代码交付时，必须在聊天框给出精确到`文件:行号`的阅读顺序（可点击跳转的链接）；与教案中的链条描述一致。
11. **新语法必须进教案（2026-09-25 学生要求）**：实际代码中首次出现的高级语法、非常规机制、第三方 API 用法，必须逐条写入当课教案 3.6 细节技术点并展开讲。
12. **阶段性授权（2026-09-26）**：学生授权 Agent 连续非交互生成第 5～7 课；期间由 Agent 自动 `git commit`（message 格式："第x课：xxx"）并 `git push`；交付时只给教案地址与代码阅读顺序，不给测试/提交指令。每课一个独立 commit。此授权仅限本次三课，之后回归默认规则（commit 由学生手动完成）。

## 教案编写规范（重中之重，每课必守）

教案文件：`TUTORIAL_DIR/教案/第XX课-课程名.md`。主体固定五部分：**前言 / 主要内容 / 技术要点 / 测试与验收 / 总结**。

### 1. 前言：先造动机，不从技术名词开始
- 必须说清：上一课已有什么 → 现在出现什么新场景 → 旧方案哪里不够 → 本课增加什么能力。
- 用真实业务场景激发兴趣，写成故事，不写"本节介绍 XX"。

### 2. 主要内容：本课地图
- 先用平铺直叙、通俗的话分步骤描述要做什么（这份文字直接决定学生读代码顺不顺）。
- 再给"文字 + 类/方法"的流程链条：构造什么输入 → 到哪个方法 → 得到什么输出/调用别的什么方法。这是学生阅读代码的顺序。多条链分别描述。
- 然后总结流程：和上一课相比，加的是"链条 / 分支 / 环节"中的哪一种（学生偏好这三个词），让人一眼明白是小的局部功能还是大的分支链条。
- 最后适当拔高：当前设计属于最基础功能，还是扩展性设计，还是优化（并发/持久化/容错/响应速度等外层包装）。

### 3. 技术要点：整份教案的核心，六个视角
- **3.0 环境配置**：涉及新依赖/新组件要给安装指导。第一课把目录当成空目录从零搭环境。学生用 VS Code，要指导插件、运行配置、测试按钮位置（每课都要跑测试，要告诉在哪点）。
- **3.1 坐标**：先告诉学生当前代码处于系统什么位置，注重横向模块/纵向层的层次感，精确定位。
- **3.2 代码**：在项目中生成代码并在教案解释。包名用个人印记（Java 用 com.shitan.*；本项目 Python，包名 `nanobot_st`）。测试以理解流程为主、数量克制。**代码与测试都要函数级中文注释**（一看就懂这个函数做什么）。结构规范、命名直观。解释代码流程用"类 xx 负责 xx，它的方法 xx 负责 xx，输入…输出…，将 xx 委托给 xx"的层次缩进语法；再按"为了实现 xx，引入了 xx；但要实现 xx 还需要 xx，所以引入了 xx"把设计故事讲通。重要类适当拟人化，突出职责，令人印象深刻。
- **3.3 数据**：涉及存储性数据给具体实例（HTTP JSON、数据库行、队列、上下文、线程池等）。讲清链条上流动的中间结果、内存级/文件级存储，**特别是那些长得像的数据类之间的前后交接关系与区别**（展示用/存盘用/适配用）。
- **3.4 状态**：数据有生命周期就画 stateDiagram，并结合代码回答谁创建、谁修改、什么条件转换、状态存在哪。
- **3.5 流程图**：每课必画。调用流程/数据流/状态流/模块交互/异步/并发/存取，优先 Mermaid（sequenceDiagram 等）。对本课新增流程画直观图。
- **3.6 细节技术点**：第三方 API 用法（json 解析、文件、数据库、网络请求）；非常规语法/注解/机制（锁、流式、异步、回调、函数式）要展开（学生习惯顺序同步思维）；非常规设计（如流程节点化）要讲；讲不清对应文字流程的常用命名词（by/from/index/route/plan/template 等）；小而巧的设计适当总结。

### 4. 测试与验收
教案里写：测什么 / 为什么测 / 输入是什么 / 预期结果 / 证明什么。
不写：VS Code 点哪里、按钮、终端操作、临时报错（这些放聊天交互）。

### 5. 总结
回答：这课比上课多了什么能力？旧设计暴露了什么问题？用了什么办法？为下一步留下什么现实问题？如发生重要设计演化可点出其在软件工程中的通称，但不强行贴标签。

### 6. 术语讲法
首次出现：大白话 → 具体例子 → 当前代码 → 正式术语。不先甩术语。

## 项目概要

- **原项目是什么**：nanobot——超轻量自托管个人 AI agent 框架（Python，异步）。跑在 WebUI/终端/聊天渠道，提供工具调用、长期记忆、MCP、多模型路由、子代理、定时自动化与 OpenAI 兼容 API。
- **解决什么问题**：用户想拥有一个自己的、可自托管、可扩展、记住自己的 AI 助手，而不依赖大平台。
- **谁使用**：个人开发者/技术爱好者（CLI/WebUI/Telegram 等）。
- **输入**：用户文本消息（可带图片/文件）。
- **输出**：AI 文本回复（流式）、工具执行效果、事件通知。
- **核心对象**：Session（会话）、Message（OpenAI 风格 dict）、AgentLoop（编排）、AgentRunner（LLM+工具循环）、Tool/ToolRegistry（工具）、LLMProvider（模型调用）、MessageBus（解耦渠道与核心）。
- **主流程**：用户消息 → MessageBus → AgentLoop（恢复会话→组装上下文→AgentRunner 循环【调 LLM→有工具调用则执行并回填→再调 LLM】→保存会话）→ OutboundMessage → 渠道回复。
